Everyone who needs to look up a CEP ends up writing the same class again, and everyone has been
bitten by ViaCEP (or any other service) going down at the worst possible moment.

**unicep** takes care of that. It queries several CEP services behind a single interface and, if
one of them goes down, it moves on to the next one by itself. You call one function and always get
the same `Address` object back, no matter who answered. It runs in the browser and on Node.js 20
or newer.

## Your first lookup

```ts
import { Unicep, defaultProviders } from '@unicep/core';

const unicep = new Unicep({ providers: defaultProviders() });

const address = await unicep.lookup('01310-100'); // with or without the hyphen
// {
//   cep: '01310100',
//   street: 'Avenida Paulista',
//   complement: 'de 612 a 1510 - lado par',
//   neighborhood: 'Bela Vista',
//   city: 'São Paulo',
//   state: 'SP',
//   ibgeCode: '3550308',
//   provider: 'viacep'
// }
```

The `provider` field tells you who answered. `complement` and `ibgeCode` might be missing,
because not every service returns them. And for CEPs that cover a whole city, `street` and
`neighborhood` come back as empty strings.

## Using it with your framework

The core is plain TypeScript and works anywhere. If you use React, Vue or Angular, the bindings
make it even easier: they look things up by themselves as soon as the user finishes typing a
valid CEP.
