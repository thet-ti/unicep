A **provider** is the adapter for one CEP service. unicep ships four, all of them work straight
from the browser (the services allow CORS) and return the same `Address`.

| Function | Service | API key | Has `complement` | Has `ibgeCode` | Has coordinates |
| --- | --- | --- | --- | --- | --- |
| `viaCep()` | [ViaCEP](https://viacep.com.br) | no | yes | yes | no |
| `brasilApi()` | [BrasilAPI](https://brasilapi.com.br) (CEP v2) | no | no | yes | yes |
| `openCep()` | [OpenCEP](https://opencep.com) | no | yes | yes | no |
| `awesomeApi()` | [AwesomeAPI](https://docs.awesomeapi.com.br/api-cep) | **yes** | no | yes | yes |

`defaultProviders()` returns ViaCEP, BrasilAPI and OpenCEP, in that order. AwesomeAPI is left out
because it needs an API key: see [AwesomeAPI key](#awesomeapi-key).

## Choosing and ordering

The order of the list is the priority. Pass only the ones you want, in the order you prefer:

```ts
import { Unicep, brasilApi, openCep, viaCep } from '@unicep/core';

const unicep = new Unicep({
  providers: [brasilApi(), viaCep(), openCep()],
});
```

### Order from configuration

To choose the order without building the list by hand (for example from an environment
variable), use `order` in `defaultProviders()`. The listed providers come first; the rest follow
as fallback:

```ts
// VITE_ADDRESS_PROVIDER="viacep,brasilapi"
defaultProviders({ order: import.meta.env.VITE_ADDRESS_PROVIDER });
// ViaCEP, BrasilAPI and then OpenCEP

defaultProviders({ order: ['opencep'] }); // OpenCEP, ViaCEP, BrasilAPI
```

The names are `viacep`, `brasilapi`, `opencep` and `awesomeapi` (case insensitive). An unknown name
throws a `TypeError` listing the valid ones.

## Configuring a provider

All built-in providers accept the same options:

| Option | What it does |
| --- | --- |
| `fetch` | Your own `fetch` implementation (default: `globalThis.fetch`). Useful for tests and proxies. |
| `baseUrl` | Changes the service address, to use a proxy or your own instance. |

```ts
import { Unicep, brasilApi, viaCep } from '@unicep/core';

const unicep = new Unicep({
  providers: [
    viaCep({ baseUrl: 'https://my-proxy.example.com/viacep' }),
    brasilApi({ fetch: myFetch }),
  ],
});
```

To apply the same options to all of them at once: `defaultProviders({ fetch: myFetch })`.

### AwesomeAPI key

AwesomeAPI needs an API key: without one, the service may rate limit or reject requests,
especially from cloud servers. That is why it is not in `defaultProviders()`. To use it, pass the
key:

```ts
// on the provider
awesomeApi({ apiKey: process.env.AWESOMEAPI_KEY });

// or in defaultProviders, which then adds AwesomeAPI at the end of the list
defaultProviders({ apiKeys: { awesomeapi: process.env.AWESOMEAPI_KEY } });
```

The key goes in the query string (`?token=`), so it triggers no CORS preflight. Use it only on the
server or behind a proxy: in the browser it would be visible to anyone.

<Aside type="note">
  In the browser, each provider only sends the `Accept` header, so there is no CORS preflight. If
  you use your own proxy, keep it that way.
</Aside>

## Writing your own provider

To use a service unicep does not have, implement the `CepProvider` interface:

```ts
import { CepNotFoundError, ProviderError, type CepProvider } from '@unicep/core';

const myProvider: CepProvider = {
  name: 'my-api',
  async lookup(cep, { signal }) {
    const response = await fetch(`https://my-api.example.com/cep/${cep}`, { signal });
    if (response.status === 404) throw new CepNotFoundError(cep);
    if (!response.ok) throw new ProviderError('my-api', `HTTP ${response.status}`);

    const data = await response.json();
    return {
      cep,
      street: data.street,
      neighborhood: data.district,
      city: data.city,
      state: data.uf,
    };
  },
};
```

Rules:

- Return the address **without** the `provider` field; unicep fills it in with the `name`.
- Throw `CepNotFoundError` when the CEP does not exist and another error (preferably
  `ProviderError`) for service failures. Only failures count against the circuit breaker.
- Pass the `signal` to `fetch`, so timeouts and cancellation work.
- The `name` must be unique within the instance.

## Using them responsibly

unicep does **not provide, host or own** any CEP data or API. It only queries independent public
services, each with its own terms, limits and availability, and it is not affiliated with any of
them.

<Aside type="caution" title="Good practices">
  - Turn on the [cache](/en/docs/core#cache) so the same lookup is not repeated.
  - Do not use unicep to crawl or validate entire databases: some services warn that heavy
    automated use may get you blocked. For bulk needs, use a downloadable database (OpenCEP
    publishes one) or host your own.
  - Read each service's terms. For business-critical commercial use, talk to the maintainers or
    run your own instance through the `baseUrl` option.
</Aside>
