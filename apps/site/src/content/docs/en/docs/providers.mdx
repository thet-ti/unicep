A **provider** is the adapter for one CEP service. unicep already comes with four. All of them
work straight from the browser (the services allow CORS) and all of them return the same
`Address` object.

| Function | Service | Has `complement` | Has `ibgeCode` |
| --- | --- | --- | --- |
| `viaCep()` | [ViaCEP](https://viacep.com.br) | yes | yes |
| `brasilApi()` | [BrasilAPI](https://brasilapi.com.br) (CEP v2) | no | yes |
| `openCep()` | [OpenCEP](https://opencep.com) | yes | yes |
| `awesomeApi()` | [AwesomeAPI](https://docs.awesomeapi.com.br/api-cep) | no | yes |

`defaultProviders()` returns all four, in that order.

## Choosing and ordering

The order of the list is the priority order: the first one is tried before the others. Pass only
the ones you want to use, in whatever order you prefer:

```ts
import { Unicep, brasilApi, openCep, viaCep } from '@unicep/core';

const unicep = new Unicep({
  providers: [brasilApi(), viaCep(), openCep()],
});
```

## Configuring a provider

All built-in providers accept the same options:

| Option | What it does |
| --- | --- |
| `fetch` | Uses your own `fetch` implementation (the default is `globalThis.fetch`). Great for tests, proxies and unusual environments. |
| `baseUrl` | Changes the service address, so you can use a proxy or your own instance. |

```ts
import { Unicep, brasilApi, viaCep } from '@unicep/core';

const unicep = new Unicep({
  providers: [
    viaCep({ baseUrl: 'https://my-proxy.example.com/viacep' }),
    brasilApi({ fetch: myFetch }),
  ],
});
```

To apply the same options to all of them at once: `defaultProviders({ fetch: myFetch })`.

<Aside type="note">
  In the browser, each provider only sends the `Accept` header, so the request triggers no CORS
  preflight. If you put your own proxy in front, try to keep it that way.
</Aside>

## Writing your own provider

If you want to use a service unicep does not have (your company's API, say), just implement the
`CepProvider` interface:

```ts
import { CepNotFoundError, ProviderError, type CepProvider } from '@unicep/core';

const myProvider: CepProvider = {
  name: 'my-api',
  async lookup(cep, { signal }) {
    const response = await fetch(`https://my-api.example.com/cep/${cep}`, { signal });
    if (response.status === 404) throw new CepNotFoundError(cep);
    if (!response.ok) throw new ProviderError('my-api', `HTTP ${response.status}`);

    const data = await response.json();
    return {
      cep,
      street: data.street,
      neighborhood: data.district,
      city: data.city,
      state: data.uf,
    };
  },
};
```

A few small rules:

- Return the address **without** the `provider` field. unicep fills it in with the `name` for you.
- When the CEP does not exist, throw a `CepNotFoundError`. For any service failure, throw another
  error (preferably a `ProviderError`). Only failures count against the circuit breaker.
- Pass the `signal` along to `fetch`, otherwise timeouts and cancellation will not work.
- The `name` must be unique within the instance.

## Using them responsibly

unicep does **not provide, host or own** any CEP data or API. It is just a client that queries
independent public services, each with its own terms, limits and availability. The project has
no affiliation with any of them.

<Aside type="caution" title="Be a good citizen">
  - Turn on the [cache](/en/docs/core#cache) so you do not repeat the same lookup for nothing.
  - Do not use unicep to crawl or validate entire databases. Some services warn that heavy
    automated use may get you blocked. If you need volume, use a database you can download
    (OpenCEP publishes one) or host your own.
  - Read each service's terms. For business-critical commercial use, it is worth talking to the
    maintainers or running your own instance through the `baseUrl` option.
</Aside>
