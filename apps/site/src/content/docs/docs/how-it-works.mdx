Por dentro, a unicep é bem simples. São só duas peças:

- **Provider**: o adaptador de um serviço de CEP. Ele faz a chamada HTTP e transforma a resposta
  no objeto `Address`, que é igual para todos.
- **`Unicep`**: recebe uma lista de providers, coloca um circuit breaker em cada um e tenta um
  por um até alguém responder.

```
 seu app ──▶ Unicep ──▶ ViaCEP ──▶ BrasilAPI ──▶ OpenCEP ──▶ AwesomeAPI
                │        (cada provider tem o seu circuit breaker)
                └── sempre devolve o mesmo objeto Address
```

## O que acontece numa consulta

1. Primeiro o CEP é validado (`01310100` ou `01310-100`). Se não for um CEP, a unicep lança um
   `InvalidCepError` na hora, sem fazer nenhuma requisição.
2. Se o [cache](/docs/core#cache) estiver ligado e o CEP já estiver lá, o endereço volta
   imediatamente.
3. Aí ela tenta os providers na ordem em que você passou. Quem estiver com o circuito aberto é
   pulado.
4. Cada tentativa tem um timeout. Se você ligou o [retry](/docs/core#retry), o mesmo provider
   ganha mais algumas chances antes de a unicep desistir dele.
5. O primeiro que responder vence, e o resultado vem com o nome dele em `provider`.

## Circuit breaker

Cada provider tem o seu próprio circuit breaker, que fica de olho nas falhas **seguidas**:

| Estado | O que significa |
| --- | --- |
| `closed` | Tudo normal. As requisições passam. |
| `open` | Depois de `failureThreshold` falhas seguidas (3 por padrão), o provider é pulado sem nem tentar a requisição. |
| `half-open` | Passado `resetTimeoutMs` (30 segundos por padrão), a unicep arrisca uma requisição de teste. Se der certo, o circuito fecha. Se não, abre de novo. |

O ganho é que um serviço fora do ar deixa de atrasar todas as consultas. Em vez de esperar o
timeout toda vez, a unicep vai direto para o próximo até o primeiro voltar.

## O que conta como falha

| O que aconteceu | Conta no circuit breaker? | O que a unicep faz |
| --- | --- | --- |
| Erro de rede, timeout, HTTP 5xx ou 429, resposta estranha | Sim | Tenta o próximo provider |
| "CEP não encontrado" | Não | Também tenta o próximo, porque a cobertura muda de um serviço para outro |
| Cancelamento por `AbortSignal` | Não | Para tudo e rejeita com o motivo do cancelamento |

Se todos os providers que responderam disseram "não encontrado", você recebe um
`CepNotFoundError`. Se nenhum conseguiu responder, o erro é um `AllProvidersFailedError`, com um
erro para cada provider. Os detalhes estão em [Erros](/docs/errors).

## Espiando o estado

```ts
unicep.status();
// [
//   { name: 'viacep', circuit: 'closed' },
//   { name: 'brasilapi', circuit: 'open' },
//   ...
// ]
```

A [página de status](/status) do projeto usa exatamente isso: ela mostra, em tempo real, se cada
provider está online, quanto tempo leva para responder e como está o circuito dele.
