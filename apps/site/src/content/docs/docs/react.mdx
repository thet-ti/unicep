O `@unicep/core` vem junto como dependência, então você não precisa instalá-lo à parte.

## Uso

```tsx
import { useState } from 'react';
import { useCep } from '@unicep/react';

export function CampoCep() {
  const [valor, setValor] = useState('');
  const { data, error, isLoading } = useCep(valor);

  return (
    <>
      <input value={valor} onChange={(e) => setValor(e.target.value)} placeholder="00000-000" />
      {isLoading && <p>Buscando…</p>}
      {error && <p>{error.message}</p>}
      {data && (
        <p>
          {data.street}, {data.neighborhood} - {data.city}/{data.state}
        </p>
      )}
    </>
  );
}
```

O hook só busca quando o valor é um CEP completo e válido (com ou sem hífen). Enquanto a pessoa
ainda está digitando, ele não faz nada, então você pode ligá-lo direto ao campo de texto. Se o
CEP muda no meio da busca, o resultado antigo some e a requisição anterior é cancelada.

## API

```ts
useCep(cep: string | null | undefined, options?: {
  unicep?: Unicep;    // padrão: instância compartilhada com todos os providers embutidos
  enabled?: boolean;  // false pausa as consultas, padrão true
}): {
  data: Address | undefined;
  error: Error | undefined;
  isLoading: boolean; // true enquanto a consulta do CEP válido atual está em andamento
}
```

O `error` é um dos [erros da unicep](/docs/errors), como `CepNotFoundError` ou
`AllProvidersFailedError`, então dá para mostrar uma mensagem diferente para cada caso.

## Usando os seus próprios providers e opções

```tsx
import { Unicep, viaCep, brasilApi } from '@unicep/core';

// Crie uma vez, fora do componente, para não perder o estado dos circuit breakers.
const unicep = new Unicep({
  providers: [viaCep(), brasilApi()],
  timeoutMs: 3000,
  cache: {},
});

const { data } = useCep(valor, { unicep });
```

Todas as opções estão em [Providers](/docs/providers) e no [Núcleo](/docs/core).
