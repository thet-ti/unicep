Um **provider** é o adaptador de um serviço de CEP. A unicep já vem com quatro. Todos funcionam
direto no navegador (os serviços liberam CORS) e todos devolvem o mesmo objeto `Address`.

| Função | Serviço | Traz `complement` | Traz `ibgeCode` |
| --- | --- | --- | --- |
| `viaCep()` | [ViaCEP](https://viacep.com.br) | sim | sim |
| `brasilApi()` | [BrasilAPI](https://brasilapi.com.br) (CEP v2) | não | sim |
| `openCep()` | [OpenCEP](https://opencep.com) | sim | sim |
| `awesomeApi()` | [AwesomeAPI](https://docs.awesomeapi.com.br/api-cep) | não | sim |

O `defaultProviders()` devolve os quatro, nessa ordem.

## Escolhendo e ordenando

A ordem da lista é a ordem de prioridade: o primeiro é tentado antes dos outros. Passe só os que
você quer usar, na ordem que preferir:

```ts
import { Unicep, brasilApi, openCep, viaCep } from '@unicep/core';

const unicep = new Unicep({
  providers: [brasilApi(), viaCep(), openCep()],
});
```

## Configurando um provider

Todos os providers embutidos aceitam as mesmas opções:

| Opção | O que faz |
| --- | --- |
| `fetch` | Usa a sua própria implementação de `fetch` (o padrão é o `globalThis.fetch`). Boa para testes, proxies e ambientes diferentes. |
| `baseUrl` | Troca o endereço do serviço, para você usar um proxy ou uma instância própria. |

```ts
import { Unicep, brasilApi, viaCep } from '@unicep/core';

const unicep = new Unicep({
  providers: [
    viaCep({ baseUrl: 'https://meu-proxy.exemplo.com/viacep' }),
    brasilApi({ fetch: meuFetch }),
  ],
});
```

Para aplicar as mesmas opções a todos de uma vez: `defaultProviders({ fetch: meuFetch })`.

<Aside type="note">
  No navegador, cada provider só envia o cabeçalho `Accept`, então a requisição não gera
  preflight de CORS. Se você usar um proxy seu, tente manter assim.
</Aside>

## Criando o seu provider

Se você quer usar um serviço que a unicep não tem (a API da sua empresa, por exemplo), basta
implementar a interface `CepProvider`:

```ts
import { CepNotFoundError, ProviderError, type CepProvider } from '@unicep/core';

const meuProvider: CepProvider = {
  name: 'minha-api',
  async lookup(cep, { signal }) {
    const response = await fetch(`https://minha-api.exemplo.com/cep/${cep}`, { signal });
    if (response.status === 404) throw new CepNotFoundError(cep);
    if (!response.ok) throw new ProviderError('minha-api', `HTTP ${response.status}`);

    const data = await response.json();
    return {
      cep,
      street: data.rua,
      neighborhood: data.bairro,
      city: data.cidade,
      state: data.uf,
    };
  },
};
```

Algumas regrinhas:

- Devolva o endereço **sem** o campo `provider`. A unicep preenche com o `name` por você.
- Quando o CEP não existe, lance um `CepNotFoundError`. Para qualquer falha do serviço, lance
  outro erro (de preferência um `ProviderError`). Só as falhas contam para o circuit breaker.
- Repasse o `signal` para o `fetch`, senão o timeout e o cancelamento não funcionam.
- O `name` precisa ser único dentro da instância.

## Usando com responsabilidade

A unicep **não fornece, não hospeda e não é dona** de nenhum dado ou API de CEP. Ela é só um
cliente que consulta serviços públicos independentes, cada um com os seus próprios termos,
limites e disponibilidade. O projeto não tem nenhuma afiliação com eles.

<Aside type="caution" title="Seja um bom cidadão">
  - Ligue o [cache](/docs/core#cache) para não repetir a mesma consulta à toa.
  - Não use a unicep para varrer ou validar bases inteiras. Alguns serviços avisam que uso
    automatizado intenso pode bloquear o seu acesso. Se você precisa de volume, use uma base
    que dê para baixar (o OpenCEP publica uma) ou hospede a sua.
  - Leia os termos de cada serviço. Para uso comercial crítico, vale conversar com os
    mantenedores ou rodar uma instância própria pela opção `baseUrl`.
</Aside>
