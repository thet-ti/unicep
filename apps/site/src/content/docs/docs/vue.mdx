O `@unicep/core` vem junto como dependência, então você não precisa instalá-lo à parte.

## Uso

```vue
<script setup lang="ts">
import { ref } from 'vue';
import { useCep } from '@unicep/vue';

const cep = ref('');
const { data, error, isLoading } = useCep(cep);
</script>

<template>
  <input v-model="cep" placeholder="00000-000" />
  <p v-if="isLoading">Buscando…</p>
  <p v-else-if="error">{{ error.message }}</p>
  <p v-else-if="data">{{ data.street }}, {{ data.neighborhood }} - {{ data.city }}/{{ data.state }}</p>
</template>
```

O composable só busca quando o valor é um CEP completo e válido (com ou sem hífen). Enquanto a
pessoa ainda está digitando, ele não faz nada, então você pode ligá-lo direto ao campo de
texto. Se o CEP muda no meio da busca, o resultado antigo some e a requisição anterior é
cancelada.

## API

```ts
useCep(cep: MaybeRefOrGetter<string | null | undefined>, options?: {
  unicep?: Unicep;                      // padrão: instância compartilhada com todos os providers
  enabled?: MaybeRefOrGetter<boolean>;  // false pausa as consultas, padrão true
}): {
  data: Ref<Address | undefined>;
  error: Ref<Error | undefined>;
  isLoading: Ref<boolean>; // true enquanto a consulta do CEP válido atual está em andamento
}
```

Tanto o `cep` quanto o `enabled` aceitam um ref, um getter ou um valor simples. O `error` é um
dos [erros da unicep](/docs/errors), como `CepNotFoundError` ou `AllProvidersFailedError`, então
dá para mostrar uma mensagem diferente para cada caso.

## Usando os seus próprios providers e opções

```ts
import { Unicep, viaCep, brasilApi } from '@unicep/core';

// Crie uma vez, num módulo, para não perder o estado dos circuit breakers.
const unicep = new Unicep({
  providers: [viaCep(), brasilApi()],
  timeoutMs: 3000,
  cache: {},
});

const { data } = useCep(cep, { unicep });
```

Todas as opções estão em [Providers](/docs/providers) e no [Núcleo](/docs/core).
