A **unicep** consulta vários serviços públicos de CEP por trás de uma única interface. Quando um
serviço cai, ela detecta a falha com um circuit breaker e troca para o próximo, devolvendo sempre
o mesmo objeto `Address`. Funciona no navegador e no Node.js 20 ou superior.

## Sua primeira consulta

```ts
import { Unicep, defaultProviders } from '@unicep/core';

const unicep = new Unicep({ providers: defaultProviders() });

const address = await unicep.lookup('01310-100'); // o hífen é opcional
// {
//   cep: '01310100',
//   street: 'Avenida Paulista',
//   complement: 'de 612 a 1510 - lado par',
//   neighborhood: 'Bela Vista',
//   city: 'São Paulo',
//   state: 'SP',
//   ibgeCode: '3550308',
//   provider: 'viacep'
// }
```

`complement` e `ibgeCode` são opcionais, porque nem todo provider devolve esses campos. Para CEPs
de cidades inteiras, `street` e `neighborhood` vêm como string vazia. O campo `provider` diz qual
serviço respondeu.

## Escolha o seu framework

O núcleo é TypeScript puro e serve para qualquer backend ou frontend. Para quem usa um framework,
há bindings que consultam sozinhos assim que o valor vira um CEP válido.
