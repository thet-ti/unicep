Todo mundo que precisa buscar um CEP acaba escrevendo a mesma classe de novo, e todo mundo
já sofreu com o ViaCEP (ou qualquer outro serviço) saindo do ar bem na hora errada.

A **unicep** resolve isso. Ela consulta vários serviços de CEP por trás de uma única interface e,
se um deles cair, passa sozinha para o próximo. Você chama uma função e recebe sempre o mesmo
objeto `Address`, não importa quem respondeu. Roda no navegador e no Node.js 20 ou mais novo.

## Sua primeira consulta

```ts
import { Unicep, defaultProviders } from '@unicep/core';

const unicep = new Unicep({ providers: defaultProviders() });

const address = await unicep.lookup('01310-100'); // com ou sem hífen
// {
//   cep: '01310100',
//   street: 'Avenida Paulista',
//   complement: 'de 612 a 1510 - lado par',
//   neighborhood: 'Bela Vista',
//   city: 'São Paulo',
//   state: 'SP',
//   ibgeCode: '3550308',
//   provider: 'viacep'
// }
```

O campo `provider` conta quem respondeu. Já `complement` e `ibgeCode` podem não vir, porque
nem todo serviço devolve essas informações. E em CEPs que cobrem uma cidade inteira, `street` e
`neighborhood` chegam como texto vazio.

## Usando com o seu framework

O núcleo é TypeScript puro e funciona em qualquer lugar. Se você usa React, Vue ou Angular, os
bindings deixam tudo ainda mais simples: eles buscam sozinhos assim que o usuário termina de
digitar um CEP válido.
